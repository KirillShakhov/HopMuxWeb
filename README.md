# HopMuxWeb

Локальная веб-оболочка для MultiHopSSH (`mssh`). Browser → React/TypeScript → FastAPI + WebSocket → `mssh` CLI → SSH. Dockerfile сверяет SHA-256 исходников **v1.2.0** и собирает CLI с командой `mssh ls HOST PATH` для просмотра каталогов по SFTP. [Релиз MultiHopSSH](https://github.com/KirillShakhov/MultiHopSSH/releases/tag/1.2.0)

## Запуск

Укажите токен в локальном `.env`. Если у вас ещё нет `~/.config/mssh/config.toml`, возьмите за основу `config/config.toml.example` и задайте хост, пользователя и способ аутентификации. Локальный `.env` исключён из Git и Docker build context.

```powershell
cd C:\Users\kirill\Pets\HopMuxWeb
docker compose up -d --build
```

Откройте [http://127.0.0.1:4444](http://127.0.0.1:4444). Для входа используйте `HOPMUX_TOKEN` из локального `.env`.

Тома Compose:

- `~/.config/mssh` → `/config`: редактируемый TOML, резервная копия `config.toml.bak` и хранилище mssh;
- `SSH_DIR` из `.env` → `/home/hopmux/.ssh` только для чтения; `key_file = "~/.ssh/…"` ссылается сюда;
- `./files` → `/files`: локальные файлы для передач и загрузок из браузера. Создайте каталог от имени пользователя, указанного в `HOPMUX_UID`, если нужен доступ на запись;
- `hopmux-data` → `/data`: история задач.

Порт опубликован только на `127.0.0.1`. Для удалённого доступа используйте HTTPS reverse proxy и отдельно настройте безопасную аутентификацию на его стороне. На Linux для записи в общий каталог `~/.config/mssh` задайте в `.env` значения `HOPMUX_UID` и `HOPMUX_GID` владельца каталога (`id -u` и `id -g` для текущего пользователя) и пересоберите образ. По умолчанию контейнер использует UID и GID 10001. При смене UID/GID у существующего контейнера обновите владельца каталога `/data` и файла `/data/transfers.json` в томе `hopmux-data`, если файл уже есть.

## Возможности

Нажмите **Создать конфигурацию** в редакторе или в разделе **Настройки → Конфигурации**, введите имя файла и добавьте первый хост. Активный TOML выбирается в верхней панели. В настройках отметьте файлы, которые должны появляться в переключателе. Кнопка «Обновить список» подхватывает файлы, добавленные напрямую в `~/.config/mssh`. При запуске без Docker можно задать `HOPMUX_CONFIG` как каталог или как путь к предпочтительному TOML.

У каждой конфигурации свои хосты, вкладки, избранное, SSH-сессии и история передач. Запущенные процессы продолжают работать при переключении. Каталог `/files` и vault mssh общие, а ссылки на отдельные окна содержат имя нужной конфигурации.

- Hosts: список, поиск, избранное, автоматический маршрут SSH по умолчанию с возможностью выбрать конкретный, отдельная проверка доступности.
- Config: граф направленных маршрутов, Visual-редактор хостов/путей, Monaco для TOML; валидация через `mssh config check`, атомарная запись и `.bak`.
- Terminal: PTY и WebSocket, resize, несколько вкладок/окон, одна активная точка ввода на `session_id`, detach/reconnect/terminate. Крестик на вкладке завершает SSH-сессию после подтверждения. Действие «Отсоединиться» и закрытие браузера оставляют CLI-процесс на сервере. Чтобы открыть его снова, выберите хост и активную SSH-сессию на странице «Хосты», затем нажмите «Вернуться к сессии».
- Ключи SSH: терминал показывает полученный отпечаток для незакреплённого ключа и оба отпечатка при несовпадении. После подтверждения HopMuxWeb сохраняет отпечаток в `host_key` и переподключает терминал с обновлённой конфигурацией.
- Transfer: две панели с независимым выбором хоста, маршрута и каталога. Копирование работает в обе стороны между `/files` и SSH-хостом и между двумя SSH-хостами. Доступны очередь, отмена, повтор, журнал, загрузка из браузера и скачивание из `/files`.
- Workspace: до четырёх панелей, изменение размера, перенос вкладок, восстановление вкладок и раскладки в этом браузере.

CLI не выдаёт надёжный поток структурированного прогресса для foreground copy, поэтому UI показывает состояния и реальные сообщения CLI без вымышленных процентов, скорости и ETA. Сессии не переживают рестарт контейнера. Конфигурации с `include` можно редактировать в Raw TOML; Visual-редактор для них заблокирован, чтобы не потерять записи из включённых файлов. Встроенные пароли скрыты в API и редакторе: обычное сохранение сохраняет прежний пароль, а замена и удаление доступны только явным действием в Visual. Для новых хостов можно использовать `password_env`.

Для копирования выберите файл или каталог в одной панели, откройте папку назначения в другой и нажмите кнопку копирования с нужной стрелкой. Перед запуском можно изменить пути и включить SHA-256. Межхостовая передача идёт потоком через `mssh` без промежуточного файла в `/files`. Если запускаете FastAPI вне Docker, для просмотра удалённых каталогов используйте `mssh`, собранный с [патчем](patches/mssh-list.patch).

## Проверки

```powershell
npm ci
npm run build
docker compose build
docker compose ps
```

Backend smoke-тест (`tests/smoke.py`) проверяет вход, реальные `mssh config check`, сохранение Raw и Visual, резервную копию, отклонение несуществующих и циклических путей, сохранение и явное изменение секретов, защиту локальных путей. Для запуска в Linux или WSL установите зависимости проекта и `httpx`. Тест использует `mssh` из `PATH` или бинарник по пути из `HOPMUX_CLI`.

## Хранилище паролей mssh

В разделе **Хранилище** можно создать vault, добавить или заменить пароли, удалить неиспользуемые записи, сменить мастер-пароль и скачать зашифрованную резервную копию. В редакторе хоста выберите **Хранилище mssh** как способ входа и укажите имя записи. Одну запись можно использовать на нескольких SSH-хостах, в том числе промежуточных.

HopMuxWeb читает и записывает штатный `vault.json` через `mssh`. Существующий файл можно положить в `~/.config/mssh/vault.json` рядом с `config.toml`. Для другого расположения задайте `HOPMUX_VAULT_FILE` в `.env` как путь **внутри контейнера**, например `/config/ssh.vault`. Для атомарной записи vault контейнеру нужен доступ на запись в родительский каталог.

Разблокировка действует 30 минут для отдельно вошедшего браузера. Проверка маршрута, открытие терминала и передача файлов запрашивают мастер-пароль при необходимости. Блокировка закрывает доступ для новых команд в этом браузере. Уже запущенные процессы `mssh` продолжают работу с загруженными учётными данными. Смена мастер-пароля сбрасывает разблокировку в остальных браузерах.

## Интеграционный SSH-стенд

Стенд из соседнего репозитория HopMux создаёт пять альтернативных маршрутов к `target`, общие jump hosts, отдельные сети и ограничения скорости. Тестовый веб-контейнер использует тот же релизный образ, но отдельный конфиг и порт `127.0.0.1:8081`; основной экземпляр на `8080` не меняется. Тестовый контейнер запускается от root только для чтения закрытого ключа стенда из Docker volume.

```powershell
cd C:\Users\kirill\Pets\HopMux
docker compose -f compose.test.yaml up -d --build --wait --wait-timeout 900

cd C:\Users\kirill\Pets\HopMuxWeb
New-Item -ItemType Directory -Path test-stand\config,test-stand\files -Force
docker cp hopmux-test-client-1:/data/config.toml test-stand\config\config.toml
docker compose -f compose.stand.yaml up -d
docker compose -f compose.stand.yaml exec -T web python -u /tests/stand_e2e.py
```

Тест проверяет пять маршрутов, upload по `target-1` и `target-5`, download по `target-2` с SHA-256, PTY по `target-4` и передачу права ввода между окнами. Дополнительные сценарии: `--auto-only`, `--terminal-only target-1`, `--terminal-only target-5`, `--terminal-only entry3-1`, `--reattach-only`. Для проверки отказа остановите `entry1`, выполните `--failover-only`, затем запустите `entry1` обратно.
